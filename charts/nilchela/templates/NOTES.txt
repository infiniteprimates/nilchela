nilchela {{ .Chart.AppVersion }} -> release "{{ .Release.Name }}" in namespace "{{ .Release.Namespace }}".

Installed with NO toolchains, deliberately: the chart ships an empty [tools]
table, because which tools an agent needs is your policy, not the chart's. The
pod runs either way — it just has nothing on PATH yet.

Pin what you want:

  # write a mise.toml with a [tools] section (see mise.toml.example), then:
  helm upgrade {{ .Release.Name }} <chart> \
    --set-file 'app-template.configMaps.config.data.mise\.toml=./mise.toml'

  # or override the whole ConfigMap key by key:
  helm upgrade {{ .Release.Name }} <chart> \
    --set 'app-template.configMaps.config.data.mise\.toml=...'

The backslashes are required — `mise.toml` is one ConfigMap key, and the dot in
it is not a path separator.

First start installs the pinned set into /tools, which can take a few minutes on
a cold volume and is near-instant afterwards:

  kubectl -n {{ .Release.Namespace }} get pods -w
  kubectl -n {{ .Release.Namespace }} logs -f <pod> -c install-tools

Bumping a tool is a mise.toml edit and a roll — the image never rebuilds.

No Service and no probes, by design. An agent host accepts no inbound traffic,
so there is nothing to front and no endpoint worth probing: the pod reports
Ready the moment the container is Running, which means "install succeeded" and
"the agent works" are two different facts. Watch the logs, and note that a
wedged agent is not restarted automatically:

  kubectl -n {{ .Release.Namespace }} logs -f <pod> -c main
